# Session 2026-06-13T17:00:15Z

## Goal
Fix routing so the default route (`/`) no longer shows the component-library
showcase but takes the user to login/signup, and make login/signup actually
work in a simple way.

## What I Did
Oriented first: read README, the frontend `app/` route tree, the auth pages,
`useAuth` store, the backend auth controller/service/DTOs, the Prisma `User`
model, and the email processor.

Key findings that shaped the approach:
- `/` (`app/page.tsx`) rendered a full atomic-design component showcase instead
  of routing anywhere — that's the "component library" the task refers to.
- Login is broken end-to-end because `email.processor.ts` is a **stub** — it
  never sends a real email, so the magic-link URL never reaches the user.
- Signup is broken because `useAuth.register()` POSTs to `/api/auth/register`,
  an endpoint that **does not exist** on the backend. The `User` model has no
  password column (`authProvider` ∈ magic_link/google/github), so password
  signup is structurally unsupported.
- The backend's real "simple" auth IS magic-link: `magic-link/send`
  find-or-creates the user (so it's signup + login in one) and `magic-link/verify`
  exchanges the token for a JWT.

Given the NEVER list forbids touching `apps/backend/src/auth/**`,
`schema.prisma`, and crypto, I built the fix around the magic-link flow the
backend already supports, without adding password auth or a register endpoint:

1. `app/page.tsx` → replaced the showcase with an auth-aware redirect: a
   spinner while `checkAuth()` resolves, then `router.replace('/dashboard')`
   if authenticated else `/login`. Mirrors the `ProtectedRoute` pattern.
2. `email.processor.ts` → log the magic-link URL via the existing NestJS
   `Logger` (not `console`) so login can be completed manually in local/dev
   until real email delivery is implemented. (Also nods to PR #48 feedback:
   logger, not console.)
3. `register/page.tsx` + `useAuth` → re-wired signup to the magic-link flow
   (the backend's actual find-or-create signup) and removed the dead
   `register()` method + `RegisterData` type that hit the nonexistent endpoint.
   The register page now reuses `LoginForm` (email-only) + `MagicLinkSent`,
   so signup no longer shows a password field the backend silently ignores.
4. `LoginForm.tsx` → added optional `title`/`description`/`footerPrompt`/
   `footerActionLabel` props (defaulting to the current copy) so the register
   page can reuse it honestly with signup wording.

## What Worked
- Following the data: tracing the actual backend capability (magic-link
  find-or-create) instead of the frontend's wishful `register` call kept the
  change inside the allowed (non-auth, non-schema) surface while still making
  signup functional.
- Reusing `LoginForm` for the register page avoided a password form the
  backend can't honor.
