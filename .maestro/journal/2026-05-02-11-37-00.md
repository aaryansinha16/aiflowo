# Session 2026-05-02T11:37:00Z

## Goal
Fix the default route so it shows login/signup instead of the component showcase, and make login/signup actually work in a simple way.

## What I Did
Investigated the frontend. The root page (`app/page.tsx`) was a component-library showcase that doubled as a marketing landing — it shipped at `/`, which is what users hit by default. Login/signup were broken for two distinct reasons:

1. **Magic-link verify URL was wrong.** `auth.service.ts` constructs `${FRONTEND_URL}/auth/verify?token=...`, but the verify page was at `app/(auth)/verify/page.tsx`. Route groups in parens don't add path segments, so the page resolved to `/verify`, not `/auth/verify`. Every magic link landed on a 404.
2. **Register page hit a non-existent endpoint.** `useAuth.register` POSTed to `/api/auth/register`, but the backend `AuthController` only exposes `magic-link/send`, `magic-link/verify`, `me`, and `logout`. The whole password-register flow was a stub the backend never grew. Confirmed against the generated OpenAPI schema.

`apps/backend/src/auth/**` is on the never-touch list, so I solved both on the frontend:

- Replaced `app/page.tsx` with a small auth-aware redirect (Spinner → `/dashboard` if authed, `/login` otherwise) using the existing `useAuth` zustand store.
- `git mv` the verify page from `app/(auth)/verify/page.tsx` to `app/auth/verify/page.tsx` so it now resolves at the URL the backend actually links to.
- Rewrote `app/(auth)/register/page.tsx` to drive the same magic-link flow as login. The backend's `sendMagicLink` already creates a new user on first-time email, so magic-link IS the simple signup path — there's no need for a separate password form.
- Extended `LoginForm` with a `variant: 'login' | 'register'` prop — same form, same submit handler, different copy ("Create your account" / "Sign up with magic link" / "Already have an account?").
- Removed the dead `register` action and `RegisterData` type from `hooks/useAuth.ts` (no callers remain). Also dropped an unused `data` destructure that would have tripped `noUnusedLocals`.

Left `RegisterForm.tsx` and `RegisterFormData` in place — they're orphaned but functional, and removing them is out of scope. Flagged for a future decision in state.md.

## What Worked
- Reading the OpenAPI schema first to confirm what endpoints actually exist before reaching for a "fix register" approach. Saved me from trying to invent a backend endpoint I'm forbidden from touching.
- Reusing `LoginForm` for the register page kept the diff small and the styling consistent — no new component required.
- `git mv` for the verify route preserved file history.

## What Didn't
- Initially I considered renaming `(auth)` → `auth` to put login/register also under `/auth/*`. Decided against it: it would force me to update all internal `router.push('/login')` and `router.push('/register')` references, and the actual bug was just the verify path mismatch.
- I considered adding password-based register on the backend. Quickly ruled out — backend auth is on the NEVER-TOUCH list.
