## Goal
Fix routing so the default route shows login/signup instead of the component
library, and make login/signup actually work (add a simple login/signup path).

## What I Did
Orientation first: read README, root + frontend `package.json`, the frontend
`app/` tree, and the auth surface. Found two distinct problems:

1. **Routing** — `apps/frontend/app/page.tsx` rendered the atomic-design
   component showcase (status badges, task cards, etc.), not an entry point.
2. **Login/signup broken** — the `useAuth` store's `register()` POSTs to
   `/api/auth/register`, but the backend (`apps/backend/src/auth/*`) exposes
   **only** magic-link routes — no register endpoint exists, so signup 404s.
   Login relies on magic-link emails, which aren't wired for local/dev.

The backend auth dir is on the NEVER-touch list, so I made login/signup work
**frontend-only**:

- Added `simpleLogin(email, name?)` to `useAuth` and rewrote `register()` to
  mint a persisted client-side session with a `demo.`-prefixed token. Updated
  `checkAuth()` to validate `demo.` tokens locally (skip `/api/auth/me`) so the
  dashboard's `ProtectedRoute` doesn't immediately evict a demo user.
- Added an optional `onSimpleLogin` prop + a "Sign in instantly (demo)" button
  to `LoginForm`, and wired `handleSimpleLogin` on the login page (validate
  email → `simpleLogin` → push `/dashboard`). Kept magic-link as the primary
  path. The register page already called `register()`, which now works.
- **Routing**: rewrote `app/page.tsx` as a redirect (`/dashboard` if
  authenticated, else `/login`) with a spinner, and moved the old showcase to
  `app/showcase/page.tsx` so it's preserved as a dev reference.

Documented the auth reality and the routing/showcase move in `context.md`, and
reset `state.md` with follow-ups (real backend sign-up, dev email delivery,
logout control).

- The `demo.` token prefix cleanly separates local sessions from real JWTs, so
  `checkAuth` needed only a one-line short-circuit.
